# PACE 代码结构与数据管线审计

审计日期：2026-11-11。主审范围为归档 step1、step2 的全部 5 个 Python 文件，以及它们与 step3 的导入、数据、路径接口。逐函数阅读并在现有快照上只读重建 `prepare()`；未下载、改写原始数据或重训模型。报告中的行号对应归档代码。复核环境为 `/private/tmp/pace-step1/venv/bin/python`。

## 结论

旧流程可重建出 77 个符合现有规则的街区，但还不是新的可复现实验框架。当前最先要处理的是原始快照覆盖保护、唯一实体标识以及包导入。几何数据没有发现明显重复 ID 或大规模断网；样本覆盖不对称、条件筛选和人工阈值则会限制研究结论。

step3 仅使用 step2 的 `block_places()`，没有使用 step2 PCA 向量。因此不能把历史 PCA 在两区共同拟合，误报成所有 step3 模型已经发生相同的数据泄漏。

## 当前快照的实测覆盖

统计口径：原窗口商业 POI 为置信度不少于 0.8 且首级类别属于 shopping、food_and_drink、lifestyle_services；纳入街区则沿用现有 `eligible` 规则。

| 最终 eligible 街区 | 24 | 53 |
| 原窗口合格商业 POI | 444 | 2,057 |

| 全区最大分量保留长度（米） | 26,931.7 | 31,237.0 |
| eligible 街区所有步行边（米） | 14,709.6 | 21,936.9 |
| eligible 街区最大 core（米） | 14,402.9 | 21,931.3 |

两区原始 POI ID 均无重复，建筑 ID 均无重复；没有恰好位于 eligible 街区边界而被 `within` 排除的合格商业 POI；没有匹配 POI 分布在两个 eligible 街区的同一建筑。`split_walk()` 的边长守恒到浮点精度，本快照没有未归属任何街区的步行边。

这些结果不支持“图大面积构坏导致模型差”的解释。更突出的是 HY 与 SoHo 的覆盖率不同、窗口边缘样本大量被排除，以及监督目标只在唯一建筑匹配子集上定义。不能把剩余样本的误差直接推广到全部商铺、城市或 Citywalk 场景。

## 每个文件的审查结果

### `step1/fetch.py`

- 下载经过临时文件再替换，单文件不会以半写入内容结束；但整套快照没有事务、覆盖保护及内容/schema 验证。
- 建筑 API 固定上限 10,000；下游 `load_buildings()` 在数量达到上限时主动拒绝，避免静默截断。当前快照未触及上限。
- Overture 发布版本固定；OSM 和建筑接口取运行时数据，重复下载不保证相同快照。manifest 只有时间和 hash，不能单靠它还原查询参数、源版本及环境。

### `step1/run.py`

- `walking_lines():52–63` 裁剪已有步行线，只保留几何，没有使用原始人流统计。`build_graph():206–236` 按线端点和入口投影切分建立无向 MultiGraph，没有把所有平面交叉点强行当成可通行节点；这个选择保留了源网络拓扑假设，但依赖源线已经正确分段。
- `load_buildings():110–117` 按来源 ID 建筑映射；当前无重复 ID。后续应显式断言唯一性，避免字典构造静默覆盖。
- `match_shops():120–144` 是点落建筑轮廓匹配，不是经过人工验证的商铺真实建筑归属；多建筑覆盖归为歧义，没有擅自选近邻。购物类别口径比 step2 商业类别窄，比较不同步骤的 POI 数必须注明。
- `snap_entrances():163–203` 检验手工配置入口是否在 OSM venue 上、标签为 main、几何连线是否穿楼，属于核验两个已指定入口。不是人流推断，也不能保证选中了访问量最大的入口或覆盖所有出入口。
- `write():31–32` 直接覆盖文件；新结果应使用唯一 run 目录和运行清单，避免指标/模型被后一次参数试验混写。

### `step2/cluster.py`

- `street_blocks():51–68` 先由命名公共道路分割出原子街区；后续相似性合并在这些原子单元上操作。原子边界并非模型学出来的。
- `absorb_road_strips():71–109` 道路带检测/吸收是几何启发式，具有 25 米、2 倍长宽比、0.65 边界占比等参数。未找到当前样本的确定性几何错误，但应将原始面→吸收后面映射纳入 processed 产物及变更审计。
- `source_graph():112–120` 取全窗口最大连通分量；`prepare():200–207` 再按街区取最长 core。选取规则排除了其他合法但断开的步行部分，因此“连通”结论针对所选 core。现有 `candidate()` 同时输出 `reachable_walk_fraction`，能够揭示 core 之外的遗失，而不是保证全区域每条路径连通。
- `adjacent():215–230` 同时要求共享边界至少 5 米和 core 有位于边界的公共节点；这比几何接壤更严格，不能仅从相邻多边形推定可步行衔接。
- `feature_vectors():233–241` 联合两区标准化，仅可作为历史探索结果；不能直接当独立区域泛化评价。
- `merge_levels():244–270` 是受邻接和最大块数 2/5/10 约束的平均链接逐步合并，能保证合并嵌套，但不是学习最优空间尺度。
- `mall_candidate():300–318` 对 HY 硬编码一个 OSM mall footprint 和一个入口，属于对照/展示，不是从 embedding 自动发现商场的证据。

### `step2/embedding.py`

- `block_places():24–43` 用唯一 eligible 街区归属、唯一建筑覆盖归属；当前样本没有边界 POI 丢失，但未来应明确边界/歧义政策并保留未分配记录，不只丢弃。
- `fit_embedding():67–120` 在两区商业 POI 足够的街区拟合类别先验、插补、缩放、PCA；各块 L2 归一化。实现与其描述基本一致，不是 GAT、GATv2 或 RGSCL。
- `merge_similar():128–146` 是邻接约束 complete linkage；最小跨组相似度达标才合并，确实不会仅靠一串近邻造成组内两端低相似度。
- `run_area():154–156` 冻结 POI 少于 5 的街区，不允许其合并。它是当前策略，不是模型证明稀疏街区不能属于某片区。
- 边界和匹配规则、最小 POI 数、PCA 维数以及停止阈值应分别记录；不能把工程几何容差与用户反对的分区相似度阈值混为一谈。

### `step2/plot.py`

- 绘图不参与训练、评价或图构建。
- 展示时固定选择阈值 0.65，且只画多街区合并组；读者应同时看到单街区比例/稀疏比例，不能仅凭图判断分区质量。
- 第 127 行颜色越界为明确的扩展性错误，见缺陷表。其余逻辑与现有两区、三尺度输出 schema 一致。

## 新流程需要固定的接口

1. 原始快照只读；每个 processed 版本记录源 hash、配置 hash、代码版本、CRS、类别和匹配规则。
2. 分开保存 `regions`、`pois`、`buildings`、`walk_nodes/edges`、`poi_building_matches`、`region_adjacency`，并对主键、外键、几何有效性及图边长守恒做入口验证。
3. 区域主键、POI 主键、建筑主键不可互换；所有缓存包含区域与快照身份。划分和 mask 保存真实实体 ID，不依赖列表顺序或偶然的本地编号。
4. 原始道路分块、embedding 学习、连通合并、候选排序各有独立输入输出；共享几何层不能隐式触发训练或重下载。
5. 实验报告至少包含“原始窗口→合格 POI→纳入街区→唯一建筑匹配→可评价 mask”的样本漏斗。只有两个地理窗口时，不把多次遮盖视作增加了独立城市样本量。
6. 新研究入口位于 `experiments/`，公共函数位于 `src/pace/`；归档代码作为可追溯历史，不继续在其中累积新实现。

## 与其他审计的交叉讨论

- 参数审计确认 step3 不消费 step2 PCA；因此联合 PCA 不是已证实的 step3 泄漏来源。
- 参数审计实证发现 RGSCL 按局部 block key 缓存建筑张量，跨区同名导致取错图；此前 RGSCL 跨区结论须由其修复/重跑后重新评估。
- 任务边界审计同意区分“分区停止阈值”和“数据定义/几何容差”，以及将完整邻接合并层次作为候选方案而非直接声称唯一正确分区。
- 我们共同认为：既不能把当前模型不佳全归因调参，也不能把裁剪和覆盖差异直接判作标签泄漏。必须先解决确定性实现错误，再在固定样本与划分上进行小规模对照。
