## 1. 首先纠正此前的判断

**旧 RGSCL 外区成绩存在实现错误，不能继续用于判断 RGSCL 是否适合 PACE、是否参数没调好。**

`step3/rgscl.py::make_graphs` 原来只按 `b001` 这样的街区编号缓存建筑图，而不同地区重复使用编号。训练 HY、测试 SoHo 时，49 个可评价街区中 12 个（241 个遮盖样本中 60 个）拿到了错误建筑图；反方向为 11 个街区中 5 个（51 个遮盖样本中 21 个）。本轮已将缓存键修为 `(area, block_id)`。同区内层选参没有这个跨区碰撞，但不能因此认为其他协议问题已消除。

旧输出留作历史证据；旧 RGSCL 和带可见统计的 RGSCL 外区误差、相对其他模型的增减以及依赖这些预测的解释，均标记为待修复重跑。这个错误不自动否定 GAT/GATv2 的独立运行，也不证明修复后的 RGSCL 一定更好。

第二个确定错误是旧下载入口可能通过软链覆盖 `data/raw` 冻结快照。现已拒绝使用已存在的目标目录，并在单文件下载前拒绝覆盖。完整 staging、schema 验证与原子发布留到新管线。

另已最小修复 step1/step3 同名 `run.py` 的导入碰撞，以及绘图超过 12 个组时的颜色索引越界。导入修复只保障现有诊断入口，尚未完成公共包重构。

修复前的源码在 `archive/2026-11-11/audit_2026-11-11/before/`，修补清单记录前后 hash。作者发布的参考代码保持原样，其缺陷记录于审计报告，不能将未审查的作者脚本当成可直接复现的金标准。

## 2. 明确研究问题与目前能回答的问题

**核心研究问题：在 RGSCL 的 POI 与建筑双视角上加入可观测的静态步行关系，能否更好地表征一个人如何进入街区、沿公共通路移动、接触并串联多个目的地？** 用未见地区的独立比较检验这种表征能否迁移。商业探索是当前重点；文化设施、广场等也是可能的步行目的地。发现连通片区与按偏好、时间预算推荐，是检验表征是否有用的下游任务。

任务链固定为：源数据与可信关联 → 微单元表征 → 基于步行邻接的相似区域连片 → 多尺度候选 → 偏好与预算条件下排序。道路围成的 block 目前只是原子观测单元；最终推荐片区应由学到的表征及连通约束形成。道路或商场现成围栏不充当学习成功的答案。

| 层次 | 输入与学习对象 | 输出/监督 | 能支持的结论 |
| --- | --- | --- | --- |
| 当前诊断任务 | 一个街区中随机可见的一半商业 POI、可见归属、建筑形态、静态步行图 | 另一半中唯一匹配建筑的 POI 的同楼成对比例 | 这些输入是否帮助补全这项统计量 |
| 表征有效性任务 | POI、建筑，以及公共入口、步行连接和目的地接入关系 | 不查看模型和输入图的独立街区相似性判断；记录判断依据和不确定性 | embedding 是否比 RGSCL 与简单静态统计更好地保留步行探索结构 |
| 候选片区任务 | 微单元 embedding + 可步行邻接 | 连通的多尺度候选集合 | 相似地点是否能形成有意义的空间候选 |
| 推荐任务 | 候选表征、用户偏好、时间预算 | 真实选择/成对偏好/后续满意度 | 排序是否有用，而非仅能回归某项地图统计 |

历史诊断标签为 `y = Σ_b n_b(n_b−1) / [N(N−1)]`，其中 `n_b` 是隐藏且唯一匹配建筑 b 的 POI 数、`N` 为这些 POI 总数。`N<2` 时标签未定义，不能直接当成 0。该诊断用来核对实现与补全能力；新主实验的评价依据是独立的步行探索相似性。随机隐藏是模拟缺失机制，并不代表现实缺失一定随机。

### 行人视角的第一组对照

先保留 RGSCL 的 POI 和建筑编码，固定街区、基础输入、训练目标与参数预算。新增信息按可核验程度分两步进入：

1. **步行网络**：从已有公共步行图提取街区内外的连接、可选路径和路段长度。在冻结的 RGSCL 向量上先加一组简单步行特征，比较 `RGSCL`、`POI/建筑/步行统计` 与 `RGSCL + 步行特征`。第一组与第三组衡量步行信息增量，第二组与第三组衡量学习表征是否超越同信息的统计基线；归一化或融合参数只在训练区拟合。
2. **入口与目的地接入**：在有证据的地方增加 `公共入口↔步行节点`、`目的地↔核验入口`，将可核验的公共室内连通作为同类步行信息。`POI 属于某栋楼` 单独保留为归属关系；不会据此增加可走边。若覆盖足够，在同输入上比较简单融合和关系编码：先沿关系交换信息，再汇总街区，检验模型是否比统计特征进一步捕捉空间结构。

室内与沿街是步行结构的实例，不是互斥的研究标签。两个不同业态的街区也可能拥有相近的进入方式、路径选择和目的地串联方式。未知入口和通路保持未知；评价需按入口覆盖分层，防止模型把地图更详细误认成更适合探索。现有两处各一个已核验入口，当前只足以测试接图逻辑；可以先用已有的室外步行底图做第一组对照。

主评价先固定观察任务与时间预算，由独立标注者做街区三元组比较：给定 A，判断 B、C 中哪个在进入方式、公共步行连通和串联多个目的地方面更接近 A，可选平局或证据不足。优先挑 POI 类别与数量相近但走法不同的难例，并纳入类别不同而走法相近的样本。正式在未见区域报告模型相似度与共识判断的一致率及覆盖率。静态输入支撑的是步行结构与探索机会；真实偏好和推荐排序另用用户选择评价。

### 三视角注意力原型

`src/pace/pedestrian_rgscl.py` 已实现独立 POI、建筑、步行编码器。POI 类别只进入 POI 图；建筑图使用轮廓形态。步行图复用 v0 的 NYCWalks 路段：节点为街区切分后的室外步行段，三个数值列为 `log1p(length_m)/5`、`cos(2θ)`、`sin(2θ)`；共享步行端点的路段才连接。步行编码先在路段图传播，再在街区内平均池化。三个 64 维向量分别经评分网络得到标量，通过 softmax 得到每块的三项权重，做加权和；缺失视角屏蔽，不分配权重。现阶段入口、人流、室内通路不输入步行编码器。

原型保留 POI↔建筑的区内对比；三视角融合结果参加区间对比，所以步行编码器和融合权重可以一起学习。按 [README](../README.md#实验环境) 安装环境后，运行 `.venv/bin/python experiments/pedestrian_rgscl.py --epochs 5 --output <新目录>` 可做两个开发区之间的训练与导出核验。两方向独立拟合，输出向量只在同一个模型空间内比较。初步核验只检查梯度、融合权重和路网拓扑对步行向量的影响，没有独立标签上的性能比较。

正式比较保留统计 concat 基线，再比较同一套三视角编码器的等权融合与注意力融合，以区分新增视角和融合方式的贡献。

## 3. 数据、模型、优化方法与评价契约

区域表征第一版的数据源、冻结范围与补标规则见 [PACE–NYC v0 数据规格](DATASET_SPEC.md)。下文的遮盖统计与选参协议用于原有代理诊断任务。

现有地理范围仅纽约 Hudson Yards 和 SoHo，77 个 eligible 街区（24/53）；至少有一次可评分遮盖的街区为 11/49。两个窗口及其测试输出已经反复用于诊断，不再作为新研究主张的未见测试集。

| 数据/特征 | 当前状态 | 对应方法与限制 |
| --- | --- | --- |
| Overture 商业 POI 类别、坐标、置信度 | 已有；当前筛 shopping/food_and_drink/lifestyle_services 且置信度≥0.8 | 类别编码/集合聚合；置信度筛选属于样本定义，须披露选择偏差 |
| NYC 建筑轮廓、面积、周长、形状 | 已有 | 数值标准化只在训练折拟合；未知建筑归属保留未知，不随意最近邻补真值 |
| POI→建筑关系 | 由点落轮廓推导，非独立人工金标准 | 可用作输入/弱监督，但隐藏 POI 的归属不得进入输入或辅助目标 |
| 步行网、道路原子块、邻接 | 已有 | 用于连通约束与空间结构；保留源线段 ID，分折清除跨集合共享实体 |
| 入口 | 仅两个指定并核验的实例 | 不足以训练或验证“主入口识别”；本轮模型未用真实访问流推断主入口 |
| 人流、营业时间、室内连通、用户行为 | 尚无用于当前训练的可靠完整输入 | 不能以设想数据描述已完成模型 |
| 独立体验/偏好标签 | 尚未采集 | 后续先制定标注规则、一致性与不确定性记录，再做监督评价 |

现阶段比较模型：可见同楼比例、训练区常数/收缩估计、正则化统计模型、GAT/GATv2，以及修复后的 RGSCL 适配版。GAT 与 GATv2 的对比要固定输入、预测头、验证预算和随机种子，另报告参数量；RGSCL 使用双视角自监督损失，再冻结编码器训练预测头，需明确它的训练目标与监督图模型不同。建筑辅助任务仅作为消融分支，不预先认定应保留。

统一契约：

1. 缓存/主键至少包含地区和街区；新管线再加入快照身份、源 POI ID。划分先于拟合，所有词表、缩放、PCA、预训练、选参仅用训练部分。
2. 静态测试区建筑与步行图可作为测试输入，属于明确允许的推理信息；禁止用测试区参与拟合。不要把允许的地图上下文与标签泄漏混淆。
3. 地理实体分组后再造遮盖；训练、验证间 purge 共享建筑/源步行段。遮盖、模型种子不算独立街区。
4. 历史同楼补全诊断的主指标为街区等权 MAE；训练也应与该估计目标对齐，避免每街区可用 mask 数不同带来的隐式权重。新表征实验用独立相似性判断，按留出地区和数据覆盖分层报告。
5. 配对误差以同一街区聚合；置信区间需尊重空间依赖。只有两个地区时，不能用 mask 数或普通逐行 bootstrap 支撑城市泛化显著性。
6. “不要自定义阈值”具体落实到不手设 embedding 合并停止阈值、不强定最终片区数。几何容差、样本定义和用户时间预算需分别说明；MDL/稳定性方法仍有建模假设，不能称为完全无参数。

## 4. 分阶段实验方向与决策

| 阶段 | 只回答一个问题 | 最小实验及对照 | 推进/停止依据 |
| --- | --- | --- | --- |
| E0 历史修复复核 | 错图影响了多少旧成绩？ | 固定旧选择、遮盖、模型种子；只修缓存重跑 RGSCL 两方向；逐行对比输入身份、旧/新预测 | 全部图身份正确、旧基线与标签完全一致后才讨论历史误差变化；复算成绩不是新表征实验的前置条件 |
| E1 统计基线与任务难度 | 建筑是否提供超越可见计数的信息？ | 直接比例、训练区常数、训练折拟合的收缩估计、正则模型；建筑特征增加/移除；保持 mask、样本、权重一致 | 若复杂模型无法稳定优于基线，保留简单估计；不要继续靠扩大网络解释该代理任务 |
| E2 行人视角表征 | 加入步行与接入信息能否带来增量？ | 首先对照 RGSCL、仅静态统计、RGSCL 加步行特征；入口证据足够后加接入关系，再检验关系编码。每次只动一类输入或一个模块 | 当前两区先做数据和构图诊断；效果以 E3 的独立标签评价 |
| E3 表征效度 | 不同地点的步行探索结构能否比较并迁移？ | 先在开发区试标街区三元组，再冻结地理留出和标注规则；用同一批独立判断比较 E2 各方法 | 标注者达成可用一致性、增强表征有可解释的增量才进入片区效果验证 |
| E4 无手设阈值的连片 | embedding 能否生成合理候选？ | 步行邻接约束完整合并树，保留多尺度候选；与纯几何候选比较；按用户预算选候选。若要求唯一分区，另做明确编码模型的 MDL 方案 | 检查连通性、遮盖/种子/原子尺度扰动稳定性、独立体验一致性；未验证前不声称自动找到“真实商圈” |
| E5 推荐验证（远期） | 候选是否改善用户选择？ | 简单偏好匹配排序为基线，对照学习排序；用独立成对偏好或真实交互评价，并检查时间预算可行性 | 没有用户相关标签时只验证代理指标和可行性，不声称推荐效果已提升 |

本轮不扩充数据。E3/E5 明确是未来数据与评价建设方向。E1/E2 使用现有窗口只能形成开发诊断；正式泛化结论需要之后预先冻结的新地区。
